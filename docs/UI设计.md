# UI 设计 · 简洁单窗方案

2026-10-24 · 第二版设计草案，待评审。

以「选择配置 → 开始导出 → 查看结果」为主线，采用 DreamCity 现有工具的浅灰底、白色内容块、蓝色按钮和一体式标题栏。

## 1. 参考与取舍

已查看两个参考项目的界面代码及美景截图上传工具的实际截图：

- [DC-Modpack-Data-Migration](../../DC-Modpack-Data-Migration/src/ui.py)：紧凑窗口、圆角白色内容块、底部状态与主按钮。
- [DC-ScenicShots-Uploader](../../DC-ScenicShots-Uploader/src/ui.py)及其[界面截图](../../DC-ScenicShots-Uploader/assets/1785322978695.png)：一体式标题栏、单列列表、选择与运行共用内容区、克制的蓝色。

采用上传工具的单窗结构与蓝色，沿用两者共同的间距、字体和控件质感。配置概要、文件规则、预检清单和日志保留在二级入口；技术约束沿用[技术文档](技术文档.md)与两份配置示例。

主界面只显示当前操作需要的信息：配置名称、版本、产物类型、勾选状态，以及底部的选择数量和开始按钮。

界面文案只保留必要的名称、状态、错误和操作。确认弹窗只显示标题、相关文件列表及按钮；内部处理流程和文件处理细节写入技术文档或日志，不作为界面说明段落。

建议窗口为 **900 × 600 DIP，固定尺寸**，长列表在内容区内滚动，底部按钮始终可见。Qt 按系统 DPI 缩放。

![待导出界面](ui-design/configs.png)

### 配置列表

- 从工作目录的 `导出/` 第一层读取任务 TOML，按文件名排序，恢复上次勾选
- 每项两行：**配置文件名**；浅灰的「包版本 · 产物类型」
- 点击复选框或行内名称切换勾选；「详情」单独打开配置详情，不改变勾选。全选支持半选态。
- 解析错误时，第二行改为简短错误，如「配置错误 · 第 12 行」；详情内提供原因与编辑入口
- 失效记忆显示为「文件已移走」项，可移除记忆

### 底部操作

- 左侧为「全选」复选框，旁边显示「已选择 2 项」或「请选择配置」。全选支持半选态。右侧只有「开始导出」。未选择时禁用。
- 点击开始即按列表顺序读取本批快照并逐项预检，完成整批目标冲突检查。已有目标文件时弹窗标题为「替换已有文件？」，提供「全部替换 / 取消」。所有替换确认后开始工作
- 运行期间锁定本批配置选择；设置和外部文件修改在下一批或重试生效。

## 3. 配置详情

点击「详情」打开宽约 620 DIP 的对话框。默认展开的内容：

| 字段      | 展示                        |
| --------- | --------------------------- |
| 整合包    | 包名与包版本                |
| 产物      | 完整包 ZIP / mrpack包 |
| Minecraft | 自动识别的游戏与加载器版本  |
| 来源      | 源实例路径                  |
| 输出      | 最终目标路径                |

其余内容以折叠项提供：

- **文件与规则**：分别列出游戏规则、额外映射、完整包自动 PCL 内容
- **预检结果**：默认「尚未检查」。点击「检查配置」后，显示输入文件数、估算体积、错误或警告；最终文件清单按需展开，和规则命中数区分。耗时扫描使用不定进度。

底部仅「编辑配置」「检查配置」，右上角关闭。编辑调用文本编辑器，不在 GUI 中维护第二套规则。预检之后配置变化时标记「需要重新检查」；正式开始仍以新快照检查。

页面中文本信息均允许选择和复制。

## 4. 导出与结果

开始后，**原列表区域切换为本批任务列表**

![导出中界面](ui-design/running.png)

任务按配置列表顺序串行执行，同一时刻仅一项正在处理。整批预检时当前项显示「正在预检」，其他待检查项显示「等待预检」；整批预检完成后，通过检查但尚未开始的任务显示「等待导出」。等待项保留「日志」「取消」入口，不显示进度条、百分比或执行耗时。当前任务完成或清理结束后，下一项自动开始；失败项不阻断队列。

每项显示：

1. 配置名，以及「日志」「取消」操作。
2. 当前阶段、真实处理量或阶段百分比、耗时。
3. 一条细进度条；扫描等未知进度使用不定样式。

文件准备阶段显示「准备文件」，随后显示复制和压缩进度；最终压缩进程正常结束即标记成功。阶段结束后清除旧百分比。

底部左侧在预检时显示「正在预检 1 项 · 等待 1 项」，导出时显示「正在导出 1 项 · 等待 1 项」；没有等待项时省略等待数量，全部结束后显示终态数量。运行时右侧按钮为「取消全部」。

取消任一项时显示「取消中」，后台作业停止并清理未完成压缩包和临时目录后再开始下一项。「取消全部」先停止队列推进，再取消每一项。

![已结束界面](ui-design/results.png)

- **成功**：行内显示「已完成」、耗时及成品名称，提供「打开目录」。多卷的精确文件组及末卷说明放入详情。
- **失败**：行内显示一行具体错误，提供「详情」，展开后查看相关路径和日志；清理失败时列出残留路径。其他任务继续。
- **取消**：显示「已取消」，移除进度条与取消按钮。
- 全部结束后显示「成功 1 · 失败 1 · 取消 0」；底部为「返回配置」及有失败时的「重试失败项」，全成功时为「打开成品目录」。
- 重试重新读取配置和设置，只重建失败任务；重新预检并确认所有需要替换的文件后执行，上批记录保留在详情中。

日志独立对话框默认展示当前任务，支持复制、打开完整日志、自动滚动；完整记录写入文件。

如果程序正在工作中，用户关闭窗口，需要弹窗确认「取消任务并退出 / 返回」。如果程序未工作状态下关闭窗口则直接退出。

## 5. 设置

![设置界面](ui-design/settings.png)

设置使用同风格的小对话框，默认仅显示三项：**输出目录、压缩等级、完整包分卷**。

「高级设置」默认收起，放压缩线程数、临时目录，并显示固定日志目录及「打开日志目录」入口。压缩线程数对应 `execution.compression_threads`，0 自动取逻辑处理器数量，正数指定当前压缩进程的工作线程上限；提示文字为「0 为自动」。自定义分卷选中后才出现数值和单位输入。底部为「取消 / 保存」。保存后影响下一批任务或重试，本批排队任务继续使用开始时的快照；成功仅提示「已保存」，失败保留输入并在对应位置反馈。

字段与默认值遵循[工具配置示例](工具配置示例.toml)：任务固定串行、压缩等级 5、分卷关闭、压缩线程数 0 自动、输出 `导出`、系统临时目录。应用数据固定放在 `导出/dc-modpack-creator/`，工具配置为其中的 `config.toml`，日志为 `logs/`；不随输出目录设置变化。界面不提供任务并发设置，工具设置不覆盖任务显式值。

分卷预设为关闭 / 1 GB / 2 GB / 4 GB / 自定义；自定义支持 MB、GB、MiB、GiB，显示换算字节。启用范围 `65,536～4,294,967,295` 字节。错误时就地提示，不常驻规范解释。mrpack包忽略全局分卷，任务显式要求分卷则预检报错。

## 6. 异常按需出现

| 场景                   | 展示方式                                                                                                 |
| ---------------------- | -------------------------------------------------------------------------------------------------------- |
| 没有配置               | 内容区居中「还没有导出配置」，下一行「将 TOML 放入“导出”文件夹」，提供「打开配置目录」；刷新仍在工具栏 |
| 工具配置损坏           | 底部持续显示「工具设置无法读取」，提供「修复」；开始禁用，保留原文件                                     |
| 任务预检失败           | 对应任务行一行原因，详情提供精确路径、行号与修复入口；其他任务继续                                       |
| 普通警告               | 行内显示「1 项警告」，详情查看；零匹配不当作失败                                                         |
| 目标文件已存在         | 整批执行前统一弹窗列出待替换文件，全部确认后才开始                                                       |
| 删除旧文件或清理失败   | 对应项详情提供具体原因及残留路径，日志记录实际处理情况                                                   |
| 打开目录、保存设置失败 | 就地保留简短原因与可复制路径，允许重试                                                                   |

单实例、源文件只读、目标冲突、覆盖确认、直接输出及失败清理按技术文档执行。内部引擎名、退出码和详细文件处理记录放入日志，日常界面不铺开。

## 7. 视觉与落地

| 项目   | 约定                                                                     |
| ------ | ------------------------------------------------------------------------ |
| 窗口   | `#F5F7FA` 浅灰底，14 DIP 圆角，细边框与轻阴影                          |
| 内容块 | `#FFFFFF`，`#DDE2E8` 边框，10 DIP 圆角；避免卡片内再套卡片           |
| 文字   | 主文字 `#182230`，次级 `#667085`；错误 `#B42318`，成功 `#287A4B` |
| 主色   | `#2F6FAD`，沿用美景截图上传工具；只用于主动作、进度与选中控件          |
| 字体   | Microsoft YaHei UI / Segoe UI；正文 13 DIP、次级 12 DIP、标题 20 DIP     |
| 间距   | 窗口内边距约 28 DIP，列表间距 10 DIP，配置行约 74 DIP                    |
| 控件   | 主按钮高 40 DIP，普通输入/按钮高 34～36 DIP；按钮圆角 7 DIP              |
| 标题栏 | 一体式可拖动标题区，右侧设置、最小化、关闭；有真实应用版本后再加小徽标   |
| 动效   | 参考现有项目短暂淡入淡出；进度变化平滑，不添加装饰动效                   |

PySide6 使用 `QMainWindow`、自绘标题栏、`QStackedWidget` 及列表模型。配置/任务共用固定内容区，详情与设置使用 `QDialog`。后台通过信号刷新，不阻塞 GUI。控件保留键盘焦点；Space 勾选、F5 刷新、Esc 关闭对话框。长路径、长错误和 100%～200% 系统缩放在实现时验证，固定窗口不得裁掉底部操作。

## 8. 本轮交付边界

上方图片和[可操作预览](ui-design/dc-modpack-ui.html)均为**示例数据**，用于评审布局、视觉和交互层级。预览支持勾选、整批替换确认、开始、取消、结果切换、详情与设置；开始及重试时用模拟已有文件展示确认弹窗；运行场景展示一项执行、其余等待，取消当前项后下一项切换为执行状态；不执行真实文件扫描、编辑、导出或目录操作。

正式桌面版按上述固定尺寸与局部滚动实现；会话预览窄屏下会重排，方便查看。程序导出逻辑及其验收仍以技术文档为准。
